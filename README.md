## Опис проєкту

**FAIMS** (First Aid Kit Information Management System) — комплексна інформаційна система для управління аптечками першої допомоги в організаціях (медичних закладах, підприємствах, навчальних установах). Система розроблена за принципами **Clean Architecture** і складається з двох основних компонентів:

1. **Серверна частина (Backend API)** — RESTful API на ASP.NET Core 9.0 з PostgreSQL, з підтримкою мультитенантності (multi-tenancy) через глобальні фільтри запитів.
2. **Мобільний застосунок (Flutter)** — кросплатформний додаток для Android та iOS, що обслуговує обидві ролі: **Адміністратора організації** (повне керування) та **Відповідальну особу** (ведення конкретної аптечки).

Мультитенантність реалізована на рівні доменної моделі: кожна сутність містить `OrganizationId`, а `ApplicationDbContext` автоматично ізолює дані організацій через `HasQueryFilter`, що гарантує, що жодна організація не може побачити дані іншої.

| Статуси медикаментів | Візуальна індикація: Good / Warning / Critical / Expired |
| Пошук | Миттєвий пошук по назві медикаменту |
| Використання | Списання з журналюванням причини |
| Поповнення | Додавання нових партій зі своїми термінами |
| Утилізація | Списання прострочених з фіксацією в журналі |
| Журнал дій | Історія всіх операцій з медикаментами |

### Серверне API

| Можливість | Опис |
|---|---|
| RESTful API | Контролери: Auth, User, Department, FirstAidKit, Dashboard, Analytics, Reporting |
| JWT Bearer | Access + refresh token з ротацією |
| Мультитенантність | Ізоляція даних через `HasQueryFilter` по `OrganizationId` |
| Хешування паролів | `IPasswordHasher<User>` з ASP.NET Identity |
| Rate limiting | 5 зап./хв на автентифікацію, 150 зап./хв на API |
| CORS | Налаштована підтримка крос-доменних запитів |
| Логування | Serilog (консоль + ротація файлів) |
| Міграції | Entity Framework Core |
| Push-сповіщення | Firebase Cloud Messaging для нагадувань про терміни придатності |
| Тестові дані | Вбудований seeder на Bogus для генерації реалістичних даних |

## Архітектура

Проєкт побудований за принципами **Clean Architecture** з чітким розподілом відповідальності:

```
┌─────────────────────────────────────────────────────────┐
│                    Клієнтський рівень                   │
│              ┌──────────────────────────┐               │
│              │  Flutter App             │               │
│              │  (Android / iOS)         │               │
│              │  Provider + GoRouter     │               │
│              └────────────┬─────────────┘               │
└───────────────────────────┼─────────────────────────────┘
                            │ HTTPS / REST + JWT
                            ▼
┌──────────────────────────────────────────────────────────┐
│                  Backend (ASP.NET Core 9.0)              │
│  ┌─────────────────────────────────────────────────┐     │
│  │  Presentation Layer — Controllers, Middleware   │     │
│  │  JWT Auth, Rate Limiting, CORS, Swagger         │     │
│  └──────────────────────┬──────────────────────────┘     │
│  ┌──────────────────────▼──────────────────────────┐     │
│  │  Application Layer — Services, DTOs, Configs    │     │
│  └──────────────────────┬──────────────────────────┘     │
│  ┌──────────────────────▼──────────────────────────┐     │
│  │  Domain Layer — Entities, Enums                 │     │
│  └──────────────────────┬──────────────────────────┘     │
│  ┌──────────────────────▼──────────────────────────┐     │
│  │  Infrastructure Layer — EF Core, Repositories,  │     │
│  │  Firebase, Password Hasher, JWT Services        │     │
│  └──────────────────────┬──────────────────────────┘     │
└─────────────────────────┼────────────────────────────────┘
                          │
                          ▼
              ┌───────────────────────┐
              │  PostgreSQL 15        │
              │  (Alpine)             │
              └───────────────────────┘
```

### Архітектурні патерни

- **Clean Architecture** — Domain → Application → Infrastructure → Backend (Presentation)
- **Repository Pattern** — абстракція доступу до даних через репозиторії
- **Multi-tenancy via Global Query Filters** — автоматична фільтрація по `OrganizationId` на рівні EF Core
- **Provider Pattern (Flutter)** — управління станом у мобільному застосунку
- **DTO Pattern** — окремі DTO для кожного use case, без витоку доменних моделей у API

## Встановлення та запуск

### Запуск backend через Docker

**1. Клонування репозиторію**

```bash
git clone <url-репозиторію>
cd FAIMS
```

**2. Налаштування змінних оточення**

```bash
cp .env.example .env
```

Відкрийте файл `.env` та встановіть необхідні значення:

```env
JWT_SECRET_KEY=ваш_секретний_ключ_мінімум_32_символи
```

> **Увага:** `JWT_SECRET_KEY` повинен містити щонайменше 32 символи.

**3. Запуск контейнерів**

```bash
docker compose up --build -d
```

**4. Перевірка працездатності**

Після успішного запуску будуть доступні:

| Сервіс | URL |
|---|---|
| Backend API | http://localhost:5076 |
| Swagger документація | http://localhost:5076/swagger |

---

### Запуск мобільного застосунку

**1. Встановлення залежностей**

```bash
cd frontend
flutter pub get
```

**2. Кодогенерація (DTO + локалізація)**

```bash
dart run build_runner build --delete-conflicting-outputs
flutter gen-l10n
```

**3. Запуск з автовизначенням IP-адреси хоста**

Linux / macOS:
```bash
./scripts/run_flutter.sh
```

Windows:
```cmd
scripts\run_flutter.bat
```

**4. Або ручний запуск із зазначенням IP**

```bash
flutter run --dart-define=API_HOST=192.168.1.100
```

> **Примітка:** Замініть `192.168.1.100` на IP-адресу машини, де запущено Backend API. Мобільний пристрій або емулятор повинен мати мережевий доступ до цієї адреси.

---

### Заповнення тестовими даними

Проєкт містить вбудований seeder на бібліотеці **Bogus**, який генерує реалістичні тестові дані: 5 організацій, підрозділи, кімнати, аптечки та медикаменти з каталогу реальних препаратів (Парацетамол, Ібупрофен, Хлоргексидин тощо) з коректно прив'язаними одиницями виміру та термінами придатності (включно з простроченими).

Для запуску seeder'а (wipe + reseed):

```bash
cd Backend
dotnet run --seed
```

Після завершення у файл `Backend/seed-credentials.txt` буде записано облікові дані всіх створених адміністраторів та відповідальних осіб для швидкого логіну.

> **Увага:** Seeder **повністю очищує** всі таблиці перед заповненням. Не запускайте на продуктивному середовищі.

| Загальне API | 150 запитів / хвилину | Усі інші ендпоінти |

## Docker-сервіси

Система розгортається у вигляді чотирьох Docker-контейнерів:

| Сервіс | Образ | Ліміт RAM | Опис |
|---|---|---|---|
| `postgres_db` | PostgreSQL 15 Alpine | 256 MB | Реляційна база даних (порт не відкритий назовні) |
| `backend` | ASP.NET Core 9.0 | 300 MB | Серверне API (трафік через Caddy) |
| `caddy` | Caddy 2 Alpine | 64 MB | Reverse proxy + автоматичний TLS (Let's Encrypt) |
| `pg_backup` | PostgreSQL 15 Alpine | 64 MB | Автоматичний бекап БД кожні 6 годин |

            HTTPS :443

## Продакшн розгортання

Система розгорнута на **DigitalOcean VPS** з автоматичним HTTPS через Caddy та DuckDNS:

| Компонент | Деталі |
|---|---|
| Хостинг | DigitalOcean Droplet (Ubuntu 24.04, 1 GB RAM) |
| Домен | [faims.duckdns.org](https://faims.duckdns.org) |
| TLS сертифікат | Let's Encrypt (автоматичне оновлення через Caddy) |
| Reverse proxy | Caddy 2 (HTTP → HTTPS редирект, проксі на backend) |
| Бекапи БД | Автоматично кожні 6 годин, зберігається 3 дні |

```bash
# Розгортання на VPS
git clone https://github.com/volkovn1kita/FAIMS.git /opt/faims
cd /opt/faims
cp .env.example .env  # заповнити змінні
docker compose up -d
```
